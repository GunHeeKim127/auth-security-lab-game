# 인증·세션·권한 우회 실험 설계

## 연구 질문

1. 인증, 세션, 권한, 토큰·요청 흐름의 취약 구현은 어떤 공격 입력을 허용하는가?
2. 서버 측 검증을 추가하면 같은 입력의 성공률과 응답 상태가 어떻게 달라지는가?
3. 각 방어 통제는 공격 성공을 차단하면서 정상 요청을 유지하는가?

## 변수

- 독립 변수: `LAB_MODE` (`vulnerable`, `secure`)
- 종속 변수: 공격 성공 여부, HTTP 상태, 응답 근거, 테스트 실행 시간
- 통제 변수: 동일 공격 입력, 동일 브라우저 엔진, 동일 로컬 호스트, 동일 애플리케이션 버전

| 영역 | 실험 수 | 주요 통제 |
|---|---:|---|
| 인증 | 4 | 균일 오류, 속도 제한, 비밀번호 정책, 위험 기반 탐지 |
| 세션 | 4 | ID 재발급, 쿠키 속성, 폐기 목록, 만료 검증 |
| 권한 | 4 | 소유권 조건, 역할 기반 접근 통제, 감사 로그 |
| 토큰·요청 흐름 | 4 | 알고리즘 고정, 토큰 버전, 단일 사용 토큰, CSRF 방어 |

## 재현 절차

1. 두 서버를 각각 3001(취약)과 3002(강화)에서 실행한다.
2. Playwright가 각 시나리오에 동일한 공격 입력을 보낸다.
3. 취약 모드에서는 공격 성공, 강화 모드에서는 차단을 기대한다.
4. JSON 결과와 HTML 리포트, 실패 시 trace를 보존한다.
5. 시나리오 ID를 논문 표·그래프·원시 로그의 공통 키로 사용한다.

본 실험은 소유한 로컬 환경에서만 수행하며 외부 시스템이나 실제 계정 정보를 대상으로 하지 않는다.
