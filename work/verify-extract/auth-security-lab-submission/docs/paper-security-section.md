# 논문 본문 확장 초안

## 제안 제목

Next.js와 PostgreSQL 기반 웹 애플리케이션의 인증·세션·권한 우회 취약점 재현 및 보안 통제 효과 비교

## 초록 초안

웹 애플리케이션의 인증과 접근 통제 실패는 계정 탈취, 세션 재사용, 다른 사용자의 데이터 접근으로 이어질 수 있다. 본 연구는 Next.js, Prisma, PostgreSQL, Playwright로 구성한 로컬 실험 환경에서 인증 4개, 세션 4개, 권한 4개, 토큰 및 요청 흐름 4개 등 총 16개 시나리오를 재현한다. 동일한 공격 입력을 취약 모드와 보안 강화 모드에 적용하고 공격 성공 여부, HTTP 상태, 판단 근거와 감사 로그를 비교한다. 최신 실행에서는 기능 비교와 실제 통합·정상 대조를 합한 68개 테스트가 모두 통과했다. 실제 PostgreSQL 세션, 객체 소유권, JWT 서명, CSRF 토큰 흐름을 확인했지만 반복 측정과 비밀번호 재설정 토큰 통합 실험은 추가로 필요하다.

## 1. 서론

인증은 사용자의 신원을 확인하고, 세션 관리는 인증 상태를 요청 사이에 유지하며, 권한 검사는 인증된 사용자가 수행할 수 있는 행위를 제한한다. 세 영역은 연결되어 있어 한 영역의 검증 누락이 다른 영역의 통제를 우회하게 만들 수 있다. OWASP Top 10은 접근 통제 실패와 식별·인증 실패를 주요 웹 보안 위험으로 분류하며, 세션 ID 재사용, 자동화 로그인 공격, 약한 비밀번호, 불완전한 로그아웃 처리를 대표 문제로 제시한다.

본 연구의 목적은 같은 애플리케이션을 취약 모드와 강화 모드로 구성하고 동일한 공격 입력을 반복 적용하여 방어 통제의 기능적 효과를 재현 가능한 자료로 제시하는 것이다. 연구 결과는 특정 제품의 보안성을 일반화하기보다, 정의된 취약 조건과 방어 조건 사이의 인과 관계를 교육·연구 환경에서 확인하는 데 초점을 둔다.

## 2. 연구 질문과 가설

- RQ1. 인증·세션·권한·토큰 흐름의 취약 구현은 정의된 공격 입력을 어느 비율로 허용하는가?
- RQ2. 서버 측 검증을 적용하면 같은 공격 입력의 성공률과 HTTP 응답이 어떻게 달라지는가?
- RQ3. 강화 통제는 공격을 차단하면서 정상 사용자의 요청 성공을 유지하는가?
- RQ4. 강화 통제는 응답시간과 운영 복잡성에 어떤 비용을 추가하는가?

가설 H1은 취약 모드의 공격 성공률이 강화 모드보다 높다는 것이다. H2는 강화 모드가 공격 성공률을 낮추면서 정상 요청 성공률을 유지한다는 것이다. H3는 강화 통제가 일부 응답시간 증가를 유발하지만 보안 효과에 비해 허용 가능한 수준이라는 것이다. 현재 1차 실험은 H1만 기능적으로 확인했으며 H2와 H3는 후속 통합 실험 대상이다.

## 3. 이론적 배경과 기준

시나리오 분류는 OWASP Top 10의 Broken Access Control 및 Identification and Authentication Failures, OWASP ASVS의 인증·세션·접근 통제 요구사항, MITRE CWE 매핑을 따른다. 비밀번호 정책은 NIST SP 800-63B의 길이·차단 목록 중심 지침을 기준으로 삼는다. JWT 실험은 RFC 7519의 등록 클레임과 RFC 8725의 허용 알고리즘 명시 및 검증 권고를 적용한다. 특히 RFC 8725는 토큰 헤더의 알고리즘 값을 그대로 신뢰하지 않고 애플리케이션이 허용 알고리즘 집합을 지정해야 한다고 설명한다.

권한 실험의 IDOR는 사용자 제어 키로 다른 사용자의 레코드에 접근하는 CWE-639와 대응한다. 방어 구현에서는 UI에서 식별자를 숨기는 방식에 의존하지 않고, 모든 데이터 접근 쿼리에 인증 사용자 또는 역할 조건을 포함해야 한다.

## 4. 위협 모델과 연구 범위

공격자는 일반 사용자 계정 또는 탈취·변조한 세션 정보를 가지고 HTTP 요청을 직접 구성할 수 있다고 가정한다. 공격자는 애플리케이션 서버나 PostgreSQL 관리자 권한은 가지지 않는다. 대상은 연구자가 소유한 localhost 환경과 비실계정에 한정하며 외부 시스템, 실제 사용자 계정, 제3자 네트워크는 대상에서 제외한다.

실험 범위에는 로그인 응답 비교, 반복 인증, 비밀번호 정책, 세션 고정·재사용·만료, 수평·수직 권한 상승, JWT 알고리즘과 수명 주기, 재설정 토큰, CSRF가 포함된다. SQL 삽입, XSS, SSRF, 공급망 보안과 운영 인프라 공격은 연구 범위에서 제외한다.

## 5. 실험 환경과 방법

실험 환경은 Windows, Node.js 20, Next.js 15, Prisma 6, PostgreSQL 15, Playwright로 구성된다. 취약 모드는 3001, 강화 모드는 3002 포트에서 실행한다. PostgreSQL에는 실험 사용자 3명, 소유 리소스 2개, 공격 결과용 감사 로그가 저장된다. 비밀번호는 bcrypt로 해시하며 실제 서비스 자격 증명은 사용하지 않는다.

독립 변수는 `LAB_MODE`이고 종속 변수는 공격 성공 여부, 정상 요청 성공 여부, HTTP 상태, 응답시간, 감사 로그 결과다. 두 모드에 같은 공격 입력과 같은 데이터셋을 적용한다. 각 시나리오 ID를 코드, 테스트, DB 감사 로그, 결과표의 공통 키로 사용한다.

1차 기능 실험은 서버 판정 함수를 HTTP API로 호출한다. 통합 실험은 실제 로그인과 bcrypt 비교, 쿠키, PostgreSQL 세션 테이블, `jose` JWT 서명, 객체 소유권 쿼리, CSRF 토큰을 사용한다. 두 결과는 논문에서 혼합하지 않고 각각 “기능 실험”과 “통합 실험”으로 구분한다.

## 6. 1차 결과

Playwright의 최신 실행은 총 68개 테스트를 수행했고 모두 예상 결과와 일치했다. 이 중 32개는 16개 판정 시나리오의 취약·강화 비교이며, 36개는 실제 동작과 정상 대조 테스트다. 통합 범위에는 사용자 열거, 반복 인증 제한, 약한 비밀번호, 세션 고정, 쿠키 속성, 로그아웃 및 만료 세션 재사용, 실제 객체 조회·수정·삭제, 관리자 역할, JWT alg=none, 비밀번호 변경 후 세션 재사용, CSRF가 포함된다. PostgreSQL에는 최신 시점 기준 세션 56건이 기록되었다.

판정 실험의 단일 회차에서 취약 모드 성공 16건과 강화 모드 차단 16건이 확인되었다. 감사 로그의 128건은 여러 실행의 누적값이므로 단일 회차 표본 수로 사용하지 않는다. 통합 테스트는 실제 DB와 암호 검증을 사용하며 정상 로그인·소유 객체·관리자·서명 JWT·정상 CSRF 요청도 성공했다. 최종 결론에는 최소 10회 반복 측정과 응답시간 통계를 추가해야 한다.

## 7. 방어 설계

인증 영역에서는 계정 존재 여부와 관계없는 균일 오류, 계정·IP 기반 속도 제한, 유출·상용 비밀번호 차단을 적용한다. 세션 영역에서는 로그인 성공 시 ID 재발급, HttpOnly·Secure·SameSite 쿠키, 서버 측 폐기, 유휴·절대 만료를 적용한다. 권한 영역에서는 인증 사용자의 소유권 또는 역할 조건을 데이터 접근 쿼리에 포함한다. JWT는 허용 알고리즘, 서명 키, `iss`, `aud`, `exp`, `nbf`를 검증하고 비밀번호 변경이나 로그아웃 시 토큰 버전 또는 세션 상태를 확인한다. 비밀번호 재설정 토큰은 난수성, 짧은 만료, 단일 사용, 해시 저장을 적용하며 상태 변경 요청은 CSRF 토큰과 Origin 검증으로 보호한다.

## 8. 타당성 위협과 한계

구성 타당성의 한계는 공격 성공을 불리언 판정으로 단순화했다는 점이다. 내부 타당성은 두 모드의 차이를 `LAB_MODE`로 제한하고 동일 입력을 사용해 확보하지만, 개발 서버 동시 실행과 캐시 상태가 응답시간에 영향을 줄 수 있다. 외적 타당성은 단일 프레임워크와 로컬 호스트 환경 때문에 제한된다. 결론 타당성은 현재 단일 회차이고 표본 수가 작아 제한된다. 최종 실험에서는 최소 10회 반복, 실행 순서 교차, 중앙값과 범위 보고가 필요하다.

## 9. 연구 윤리와 안전

모든 공격은 연구자가 소유한 localhost 환경에서 비실계정을 대상으로 수행한다. 프로젝트는 외부 네트워크에 공개하지 않고 실제 비밀번호나 개인정보를 저장하지 않는다. 공격 절차는 방어 효과 검증에 필요한 수준으로 제한하며 제3자 시스템에 적용하지 않는다. 결과 파일에는 연결 문자열과 비밀키를 포함하지 않는다.

## 10. 잠정 결론

1차 실험은 정의한 16개 취약 조건에서 서버 측 방어 통제가 공격 판정을 일관되게 차단함을 보여 주었다. 또한 시나리오 ID를 테스트와 PostgreSQL 감사 로그에 공통으로 사용하여 결과 추적 가능성을 확보했다. 최종 논문에서는 실제 세션과 객체 접근을 사용하는 통합 실험, 정상 요청 대조군, 반복 측정 결과를 추가한 뒤 방어 효과와 성능 비용을 함께 평가해야 한다.
